# タスク構成の規則（16エピソード・7ラウンドのベンチで検証済み・厳守）

- タスク=目的を持った作業単位。アプリ訪問ではない（「ブラウザを見てた」は失格、「◯◯のデザイン確認」が合格）
- idle放置・開いてるだけのタブ・1分未満の一瞥はタスクにしない。典型3〜10個/45分
- 同じ目的のapp横断断片は1タスクに統合(cross_app)。例: ターミナルで指示→ブラウザで確認→チャットで共有は1タスク
- 同一ワークスペース/タブで連続・並行起動したAIエージェント群は、目的が近ければ1タスク（指示1本ごとに分割しない）
- 前面での閲覧/編集と背面エージェントの稼働は、目的が同じでも**別タスク**（重なるspanのまま並行に数える）
- 作業タブへの一瞥は「そのタブが今レビュー中の成果物を作ったか」で帰属。無関係なタブの監視は独立タスク
- span=実際に進んでいた区間だけ。数分以内の離脱では切らない・一瞥で延長しない・idle区間は含めない・終端は最後の実活動
- status: **done**=明示的完了シグナル（送信/保存/commit/公開/エージェント完了表示/稼働リスト消滅/結果受領）がある時だけ。**ongoing**=終端時点で稼働・注視中。**paused**=完了シグナルなしに離脱して戻らない（閲覧・検索系の離脱は原則paused）
- 名前=初見のエージェントが理解できる具体名。タブ/ワークスペース名は画面表記のまま（誤記も含めて）使う
- 各タスクにevidence（ログから一字一句コピーした実在断片）を必須で付ける。name/goal/属性はevidenceの事実だけで構成。ログに無い分類（「EC系YouTuber」等）や続き判定を周囲の文脈から推測して足すのは捏造＝失格。根拠が薄い時は発明せず画面表記のまま素朴に書く（evidenceが出せないタスクは出力しない）

# 覚えたこと（facts）の規則 — タスクと同じ根拠グラウンディングで抽出
- facts=タスクと別に「次にAIへ渡す価値がある具体的事実」。種類は person（人・相手）/ deadline（締切・期日）/ decision（決まったこと・承認・方針）/ project（案件名・ブランド名）の4つだけ
- 全factに evidence（ログから一字一句コピーした実在断片）を必須で付ける。ログに無い人名・日付・決定は絶対に出さない（自分の推測で締切を作らない）
- value は画面表記のまま（「田中さん」「7/31」「口頭承認OK」）。deadline は when にISO日付（推定できる年月は窓の日付から補う）、person は detail に役割（送り手/相手/担当）、decision は detail に誰が/何を
- task_id で由来タスクに紐付ける。同じ事実は1回だけ（窓内で重複させない）。典型0〜5件/窓。無ければ空配列
